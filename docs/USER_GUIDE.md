# 使用指南

ASMR Dubber 把一次配音工作保存成项目。识别、翻译、校对、合成和混音彼此分开，每一步完成后
都会写入磁盘。你可以处理到一半关闭程序，之后从“最近项目”继续。

## 第一次启动

浏览器打开后先进入“设置 → 设备与模型”，确认计划使用的 ASR（语音识别）和 TTS（语音
合成）后端。状态为“可用”才能直接运行；“模型不完整”表示依赖存在但模型文件没准备好；
“未安装”表示运行环境也需要安装或修复。

然后完成两项基本设置：

1. 在“翻译”中选择服务、模型和接口地址，保存当前服务的 API Key；
2. 在“TTS（语音合成）”中选择本地 IndexTTS2 或已经启动的外部 API。

设置页底部有两个保存按钮：

- **仅保存为以后新项目默认值**：保存这张表单，但不修改当前打开的项目；
- **保存并应用到当前项目**：保存默认值，同时把设置写入当前项目。

每个新项目会复制一份当时的默认设置。以后修改全局默认值，不会暗中改变已有项目。如果当前
项目已经做过识别，而你应用了影响识别的设置，页面会把现有结果标成待更新；下一次运行 ASR
会按新设置重做。

## 1. 创建或打开项目

在“项目工作台”选择日语音频或视频，点击“新建项目”。程序会：

- 在项目目录保存输入文件的原字节副本；
- 记录文件 SHA-256、时长、采样率、声道和视频信息；
- 写入当前设置快照；
- 建立分析、参考音频、中文缓存、输出和字幕目录。

原文件不会被裁剪或覆盖。项目名来自文件名，并附带时间标记以免覆盖同名项目。

继续已有项目时，从“最近项目”选择并点击“打开项目”。也可以把 `project.json` 的完整路径
粘贴到下拉框。需要搬运项目时复制整个项目目录，而不是只复制 manifest。

### 已有台本或字幕时

展开“已有台本或字幕（可跳过 ASR）”，可以选择文件，也可以直接粘贴文字：

- SRT、VTT、ASS/SSA、LRC 自带时间戳，程序直接用它们建立句子表，不再运行 ASR 或自动切分；
- TXT 和粘贴的纯文本按每个非空行作为一句；只有一个长段落时，会先按日文句末标点拆分；
- 纯文本可以按台词长度生成初始时间轴，也可以使用进阶组件中的 Qwen3 ForcedAligner 对齐。

Qwen3 ForcedAligner 会按不超过五分钟的音频区间分组处理。纯文本缺少原始时间信息，无论选择
估算还是自动对齐，都应在句子表中抽查开始、结束和漏行。导入会替换当前句子表，但不会改动
项目原媒体；原台本文字和导入报告保存在项目的 `imports` 目录。

## 2. 识别日文

ASR（语音识别）设置分成三件互不绑定的事：先判断哪些区域有语音，再识别文字，最后决定用
哪套时间戳。这样可以自由组合，例如用 ASMR 专用 VAD 预处理、Parakeet 识别，再用 Qwen3
ForcedAligner 重算句子边界。

### 选择识别模型

- **Parakeet 日语**：默认选择。1.1B 质量优先，0.6B 更省资源；
- **Kotoba-Whisper**：日语 Whisper 系列，适合和 Parakeet 对照；
- **Faster-Whisper**：CTranslate2 实现，CPU `int8` 和 GPU 模式都比较实用。

网页只显示当前后端相关的参数。Parakeet 的解码头、Kotoba 的分块长度和 Faster-Whisper 的
计算精度不会混在一起显示。批大小保持 1 最稳妥；提高批大小可能增加吞吐，也会增加显存占用，
并可能带来细微结果差异。

“日文识别提示词”适合写人名、作品名和特殊读法，不适合放整段预期台词。提示词是线索，不是
识别证据。

### VAD（语音活动检测）

VAD 在识别前找出可能包含人声的区间：

- **不做 VAD 预处理**：保留所有低响度内容，ASMR 通常先从这里开始；
- **后端自带 VAD**：只在 Parakeet 和 Faster-Whisper 等实际支持的后端显示；
- **日语 ASMR 专用 Whisper VAD**：独立 ONNX 模型，可与任一支持的识别模型组合。

VAD 能减少长静音和部分幻觉，但阈值太高会删掉耳语、呼吸声旁的轻声台词。发现漏句时，先
关闭 VAD 做一次对照；使用 ASMR 专用 VAD 时再尝试降低语音阈值或增加边界保留时间。

### 时间戳

默认保留识别模型给出的时间。安装 Qwen3 ForcedAligner 0.6B 后，可以让它根据识别出的日文
重新计算起止边界。它不会改写识别文字，也不是第四种 ASR 后端。某一句对齐失败时，程序保留
原时间，并把原因写入 `analysis/asr_forced_alignment.json`。

### 多模型交叉校对

启用后，程序让多个本地识别模型依次处理同一音频，再把候选交给所选 LLM 判断。参与模型、
文字优先来源和时间戳来源只列出**模型文件完整且运行环境可用**的项目；没有下载的模型不会
出现在列表里。

使用前要知道：

- 各识别器串行运行，总耗时大致相加；
- 每个模型仍需单独满足内存和显存条件；
- 交叉校对需要 DeepSeek、OpenAI、Claude、Gemini 或 OpenAI-compatible LLM；
- DeepL、Google Cloud Translation 和 Microsoft Translator 不能承担候选校对；
- “作品、人物与场景背景”只用于专名和消歧，不能成为补写台词的依据；
- 候选和裁决记录保存在 `analysis/asr_candidates.json` 与
  `analysis/asr_review.json`，便于复查。

独立 ASMR VAD 会预处理每个候选。选择“后端自带 VAD”时，只对实际支持的候选生效，不会
强行套到 Kotoba-Whisper 上。

### 运行和重跑

点击“运行 ASR（语音识别）”后，程序生成 16 kHz 单声道分析副本并开始识别。分析副本只供
模型使用，混音始终基于原媒体。

已经有识别表格时再次点击该按钮，会按当前项目设置重新识别。重跑前先保存需要保留的人工
内容；新的识别时间轴可能改变句子 ID 和分段，原来的逐句中文与配音缓存不应被当作仍然匹配。

## 3. 校对和翻译

识别结果出现在句子表格中：

| 列 | 用途 |
|---|---|
| 句子 ID | 项目内稳定引用；不要手工制造重复 ID |
| 启用中文处理 | 关闭后该句保留在时间轴，但不参与翻译和配音 |
| 开始/结束 | 日语原句的秒数边界 |
| 日文原文 | 可人工修正的识别文本 |
| 中文译文 | 可人工改写的配音文本 |
| 提前开始 | 只覆盖这一句的中文提前秒数；留空使用全局值 |

先检查明显错字、漏字、重复句和边界，再点击“翻译日文”。翻译完成后重点检查人名、称呼、
语气和中文长度。纯笑声、呼吸、呻吟、亲吻声等没有实义文字的句子会保留日文行，但中文通常
为空，也不会合成。

编辑完成后点击“保存校对表格”。运行翻译、合成、混音或字幕前，页面也会读取当前表格，
但明确保存一次更容易确认磁盘内容。不要在两个浏览器窗口同时修改同一项目；如果磁盘 revision
已经变化，较旧窗口会收到冲突提示，而不是覆盖较新的内容。

### 翻译服务的区别

LLM 服务能使用相邻句上下文、自定义 Prompt 和翻译记忆，更适合口语、代词和连续场景。普通
机器翻译服务按句处理，更直接，也不会显示无关的 Temperature、Top P 或 Prompt 设置。


## 4. 选择音色参考

展开“统一音色参考”，从项目句子中选择一条 5–15 秒的清晰日文。理想参考具备这些条件：

- 只有一个说话人；
- 有正常可辨的语音，不是纯气声或音效；
- 背景音乐和环境声较弱；
- 没有明显削波、混响或多人重叠。

点击“设为项目音色参考”后可以试听截取结果。这个选择属于当前项目，不会因应用全局设置而
被清空。

如果使用外部参考音频，文件会复制到 `.asmr-dubber/config/references`。GPT-SoVITS、Fish
Speech 等需要参考文字的服务必须填写与音频准确对应的日文；文字错位会明显影响结果。

## 5. TTS（语音合成）与混音

点击“TTS（语音合成）并混音”会先生成缺失或缓存已失效的中文句子，再建立中文轨并混入原轨。
修改中文、参考音频、合成模型或相关参数后，受影响的缓存键会变化；没变化的句子可以直接复用。

### IndexTTS2 参考方式

IndexTTS2 把音色和情绪分开：

- 音色默认使用项目统一参考句，也可跟随当前句或使用外部音频；
- 情绪默认跟随当前日语句，也可使用项目参考、音色参考、外部音频或文字描述；
- 同一角色建议保持统一音色参考，多角色项目再考虑逐句参考；
- 参考过短、只有呼吸声或背景音乐太强时，音色更容易漂移。

### 外部 TTS API

程序只调用服务，不会替你启动 GPT-SoVITS、CosyVoice 或 Fish Speech。先确认服务端能独立
生成音频，再填写接口地址。GPT-SoVITS 请求会传参考文件路径；Docker 或远程服务必须能通过
挂载或路径映射访问该文件。外部并发默认是 2，服务不稳定时先降到 1。

### 中文开始时间

中文默认允许在日语结束前开始，以减少译文比原句长造成的拖尾。正数提前量按两个上限中较小的
一个计算：

```text
实际提前量 = min(最多提前秒数, 日语句长 × 百分比)
中文开始时间 = 日语结束时间 - 实际提前量
```

例如一句日语长 4 秒，全局设置为最多提前 5 秒、最多占句长 50%，实际只提前 2 秒。数值为
`0` 时从日语句末开始；负数表示在句末后等待。表格中的逐句值覆盖全局秒数，但仍受百分比
上限约束。

### 响度和峰值

默认设置会把每句中文的活动响度跟随对应日语片段，并让中文略低于原声。一般先听默认结果，
再调整“中文相对原声响度”；不要同时大幅提高相对响度和额外增益。单句、中文中间轨和最终
混音各有峰值保护，能降低叠加时削波的概率，但不能修复输入或 TTS 本身已经失真的音频。

### 多声道路由

TTS 输出通常是单声道。“自动（优先中置）”决定这条单声道中文该写进原媒体的哪些声道：

- 单声道输入仍输出单声道；
- 立体声输入把中文送到左右两个声道；
- 3.0、5.1、7.1 等多声道输入优先只送到中置声道；
- 无法可靠识别布局时也采用单声道位置的安全回退，避免把人声铺满环绕声道。

“复制到全部声道”会把中文复制到每个声道，通常只用于你明确知道下游需要这种布局的情况。

## 6. 字幕

识别完成后就能生成字幕，不必先做 TTS。可选择：

- 日中双语；
- 仅中文；
- 仅日文。

每次会生成 SRT 和 LRC。视频项目还会生成带字幕视频：环境支持时烧录字幕；如果缺少可用的
字幕滤镜或编码器，会退回到带可选择字幕轨的封装方式。

字幕时间轴可以使用原日语边界，也可以跟随中文配音时间。默认可读性限制为每行 22 个字符、
最短显示 1 秒、最多 18 字/秒。中文改长后如果字幕闪得太快，应延长边界或降低每秒字符数，
而不是只增加单行长度。

## 输出和恢复

最终音频保存在 `output` 下，采用 24-bit WAV。视频项目会尽量保留原画面、原音轨、字幕、
附件和 metadata，并附加混音后的音轨。字幕和表格导出分别在 `subtitles` 与 `exports`。

长任务中断后重新打开项目即可继续：

- 已保存的识别、翻译和表格不会因为浏览器关闭而丢失；
- TTS 按句缓存，只重做缺失或输入签名变化的句子；
- 输出先写临时文件，完整完成后才替换正式文件；
- `performance.json` 记录各阶段耗时和缓存命中，不记录 API Key 或 Prompt 正文。

执行 ASR、台本对齐、翻译、TTS、混音或字幕视频时，可以点击“取消当前执行”。程序会停止当前
子进程，并在安全检查点退出；已经保存的翻译和逐句 TTS 缓存会保留，ASR 未完成时继续保留
取消前的句子表。

“日志与诊断”页显示最近的程序日志，并提供完整日志下载。日志保存在
`.asmr-dubber/logs/asmr-dubber.log`，达到大小限制后自动轮转。API Key 和常见令牌会在写入前
隐藏，但日志仍可能包含本机路径、模型名和错误响应，公开提交前应自行检查。

页面底部的“项目诊断”会列出当前阶段、缺少的内容和输出路径。遇到问题先看这里，再查看
[排障指南](TROUBLESHOOTING.md)。

## 隐私和密钥

输入媒体和本地模型处理都留在程序目录，但翻译服务和外部 TTS API 会收到完成任务所需的文字
或参考音频。是否上传取决于你选择的后端，请阅读相应服务的数据政策。

保存的 API Key 以明文位于 `.asmr-dubber/config/secrets.json`。密码框不回显旧值，只有点击
对应的“清除”按钮才会删除。不要分享程序目录、日志中的私人路径、项目媒体或密钥文件。
