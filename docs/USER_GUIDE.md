# 使用指南

ASMR Dubber 把一次配音工作保存成项目。识别、翻译、校对、合成和混音彼此分开，每一步完成后都会写入磁盘。你可以处理到一半关闭程序，之后从“最近项目”继续。

## 第一次启动

浏览器打开后先进入“设置 → 设备与模型”，确认计划使用的 ASR（语音识别）和 TTS（语音合成）后端。状态为“可用”才能直接运行；“模型不完整”表示依赖存在但模型文件没准备好；“未安装”表示运行环境也需要安装或修复。

然后完成三项基本设置：

1. 在“ASR（语音识别）”中选择新项目的音频语言和识别方式；
2. 在“翻译”中选择服务、模型和接口地址，保存当前服务的 API Key；
3. 在“TTS（语音合成）”中选择本地/云端 IndexTTS2、通用 TTS API、Edge TTS 或其它云端服务。

Edge TTS 不需要 API Key。IndexTTS2 未安装、独立运行环境损坏或 checkpoints 不完整时，程序会把 Edge TTS 作为新项目的默认后端；已经保存的项目设置不会被自动改写。

设置页底部有两个保存按钮：

- **仅保存为以后新项目默认值**：保存这张表单，但不修改当前打开的项目；
- **保存并应用到当前项目**：保存默认值，同时把设置写入当前项目。

每个新项目会复制一份当时的默认设置。以后修改全局默认值，不会暗中改变已有项目。如果当前项目已经做过识别，而你应用了影响识别的设置，页面会把现有结果标成待更新；下一次运行 ASR 会按新设置重做。

## 1. 创建或打开项目

先在“设置 → ASR（语音识别）”确认新项目的音频语言并保存。回到“单个作品”选择音频或视频，再点击“新建项目”。程序会：

- 在项目目录保存输入文件的原字节副本；
- 记录文件 SHA-256、时长、采样率、声道和视频信息；
- 写入当前设置快照；
- 建立分析、参考音频、中文缓存、输出和字幕目录。

原文件不会被裁剪或覆盖。项目名来自文件名，并附带时间标记以免覆盖同名项目。

继续已有项目时，从“最近项目”选择并点击“打开项目”。也可以把 `project.json` 的完整路径粘贴到下拉框。需要搬运项目时复制整个项目目录，而不是只复制 manifest。

### 已有台本或字幕时

展开“使用已有台本或字幕（可选）”，可以选择文件，也可以直接粘贴文字：

不少音声作品提供的是按音轨整理的纯文本台本，只有 LRC、VTT 等字幕文件带有时间轴。前者适合使用智能台本校对，后者直接导入更稳妥。

- “原文台本或字幕”直接沿用当前项目的日语或英语设置，之后仍需翻译；
- “中文配音稿或中文字幕”直接进入中文列，可以跳过 ASR 和翻译；
- SRT、VTT、ASS/SSA、LRC 自带时间戳，程序直接用它们建立句子表，不再运行 ASR 或自动切分；
- TXT 和粘贴的纯文本按每个非空行作为一句；只有一个长段落时，会先按源语言或中文句末标点拆分；
- 日语或英语纯文本可以按台词长度生成初始时间轴，也可以使用进阶组件中的 Qwen3 ForcedAligner 对齐；中文纯文本可以按长度估算，或使用下面的智能台本校对，不单独使用 Qwen3。

如果台本没有时间轴，可以选择“先运行 ASR/翻译，再用大模型校对台本”。程序会先用当前 ASR 设置得到真实时间轴；中文台本还会先完成一次中文翻译。随后，大模型只负责把台本文字映射到这些已有区间，不会重新猜测时间，也不会改动原音频。这个方式需要 DeepSeek、百炼、豆包、商汤、OpenAI、Claude、Gemini 或本地 OpenAI-compatible 等大模型服务，并且会比直接导入多一次处理时间；带时间轴的字幕仍然直接导入。

Qwen3 ForcedAligner 会按不超过五分钟的音频区间分组处理。纯文本缺少原始时间信息，即使使用自动对齐或智能台本校对，也应在句子表中抽查开始、结束和漏行。导入会替换当前句子表，但不会改动项目原媒体；原台本文字和导入报告保存在项目的 `imports` 目录。

## 2. 识别源语言

ASR（语音识别）设置分成三件互不绑定的事：先判断哪些区域有语音，再识别文字，最后决定用哪套时间戳。这样可以自由组合，例如用 ASMR 专用 VAD 预处理、Parakeet 识别，再用 Qwen3 ForcedAligner 重算句子边界。

在设置中选择英语后，页面只显示可用于英语的 Faster-Whisper 模型和 VAD。新建项目时会向模型传入 `language=en`。Parakeet、Kotoba-Whisper 和日语 ASMR 专用 VAD 不会出现在英语配置中，也不需要另外下载英语专用模型。

### 选择识别模型

- **Parakeet（日语）**：默认选择。1.1B 质量优先，0.6B 更省资源；
- **Kotoba-Whisper（日语）**：日语 Whisper 系列，适合和 Parakeet 对照；
- **Faster-Whisper（日语/英语）**：CTranslate2 实现，CPU `int8` 和 GPU 模式都比较实用。

安装方案准备的是 Faster-Whisper large-v2。需要 large-v3 时，按[后端指南](BACKENDS.md#使用-large-v3)安装到本地目录后再选择。

网页只显示当前后端相关的参数。Parakeet 的解码头、Kotoba 的分块长度和 Faster-Whisper 的计算精度不会混在一起显示。批大小保持 1 最稳妥；提高批大小可能增加吞吐，也会增加显存占用，并可能带来细微结果差异。

“识别提示词”适合写人名、作品名和特殊读法，不适合放整段预期台词。提示词是线索，不是识别证据。英语项目也可以填写英文专名或读法提示。

### VAD（语音活动检测）

VAD 在识别前找出可能包含人声的区间：

- **不做 VAD 预处理**：保留所有低响度内容，ASMR 通常先从这里开始；
- **后端自带 VAD**：只在 Parakeet 和 Faster-Whisper 等实际支持的后端显示；
- **日语 ASMR 专用 Whisper VAD**：独立 ONNX 模型，只用于日语，可与日语识别模型组合。

VAD 能减少长静音和部分幻觉，但阈值太高会删掉耳语、呼吸声旁的轻声台词。发现漏句时，先关闭 VAD 做一次对照；使用 ASMR 专用 VAD 时再尝试降低语音阈值或增加边界保留时间。

### 时间戳

默认保留识别模型给出的时间。安装 Qwen3 ForcedAligner 0.6B 后，可以让它根据识别出的日语或英语重新计算起止边界。它不会改写识别文字，也不是第四种 ASR 后端。某一句对齐失败时，程序保留原时间，并把原因写入 `analysis/asr_forced_alignment.json`。

### 多模型交叉校对

启用后，程序让多个本地识别模型依次处理同一音频。不同模型的长短句会先按全文字符和时间范围对齐，再投影到共同的比较窗口。文字近似一致时由程序直接裁决，仍有争议的窗口才交给所选 LLM。参与模型、文字优先来源和时间戳来源只列出**模型文件完整且运行环境可用**的项目；没有下载的模型不会出现在列表里。

使用前要知道：

- 各识别器串行运行，总耗时大致相加；
- 每个模型仍需单独满足内存和显存条件；
- 交叉校对需要 DeepSeek、阿里云百炼、豆包、商汤 SenseNova、OpenAI、Claude、Gemini 或 OpenAI-compatible LLM；
- DeepL、Google Cloud Translation 和 Microsoft Translator 不能承担候选校对；
- “作品、人物与场景背景”只用于专名和消歧，不能成为补写台词的依据；
- Parakeet、Whisper 等同系列模型按一个模型家族计票，避免相近模型重复计票形成虚假多数；
- LLM 只能选择现有候选，置信度不足时程序会回退并在项目诊断中标记需要核对；
- 候选和裁决记录保存在 `analysis/asr_candidates.json` 与 `analysis/asr_review.json`，便于复查。

独立 ASMR VAD 会预处理每个候选。选择“后端自带 VAD”时，只对实际支持的候选生效，不会强行套到 Kotoba-Whisper 上。

### 运行和重跑

点击“运行 ASR（语音识别）”后，程序生成 16 kHz 单声道分析副本并开始识别。分析副本只供模型使用，混音始终基于原媒体。

已经有识别表格时再次点击该按钮，会按当前项目设置重新识别。重跑前先保存需要保留的人工内容；新的识别时间轴可能改变句子 ID 和分段，原来的逐句中文与配音缓存不应被当作仍然匹配。

## 3. 校对和翻译

识别结果出现在句子表格中：

| 列 | 用途 |
|---|---|
| 句子 ID | 项目内稳定引用；不要手工制造重复 ID |
| 启用中文处理 | 关闭后该句保留在时间轴，但不参与翻译和配音 |
| 开始/结束 | 源语言句子的秒数边界 |
| 源语言原文 | 可人工修正的识别文本 |
| 中文译文 | 可人工改写的配音文本 |

先检查明显错字、漏字、重复句和边界。识别结果或日语/英语台本需要点击“翻译为中文”；导入中文台本后不需要再翻译，确认中文和时间轴无误即可直接配音。纯笑声、呼吸、呻吟、亲吻声等没有实义文字的句子会保留源文行，但中文通常为空，也不会合成。需要删除一句时，把该行的源文和中文都清空；保存表格或开始下一项操作后，这一行会从项目中移除。

编辑完成后点击“保存校对表格”。运行翻译、合成、混音或字幕前，页面也会读取当前表格，但明确保存一次更容易确认磁盘内容。不要在两个浏览器窗口同时修改同一项目；如果磁盘 revision 已经变化，较旧窗口会收到冲突提示，而不是覆盖较新的内容。

### 翻译服务的区别

LLM 服务能使用相邻句上下文、自定义 Prompt 和翻译记忆，更适合口语、代词和连续场景。普通机器翻译服务按句处理，更直接，也不会显示无关的 Temperature、Top P 或 Prompt 设置。

| 服务 | 适合场景 | 配置要点 |
|---|---|---|
| DeepSeek | 默认选择 | 默认模型 `deepseek-v4-flash` |
| 阿里云百炼 | 使用百炼中的 Qwen 或其它兼容模型 | API Key、地域和基础地址必须匹配 |
| 豆包（火山方舟）| 使用豆包模型或方舟推理接入点 | 填写控制台可用的模型或接入点 ID |
| OpenAI、Claude、Gemini | 使用各自官方 API | 保存对应服务的 API Key |
| OpenAI-compatible | 本地或自建兼容接口 | 填写实际地址和模型 ID |
| DeepL、Google Cloud、Microsoft Azure | 普通机器翻译 | 不参与台本或多 ASR 校对 |


## 4. 选择音色参考

展开“统一音色参考”，从项目句子中选择一条 5–15 秒的清晰台词。理想参考具备这些条件：

- 只有一个说话人；
- 有正常可辨的语音，不是纯气声或音效；
- 背景音乐和环境声较弱；
- 没有明显削波、混响或多人重叠。

点击“设为项目音色参考”后可以试听截取结果。这个选择属于当前项目，不会因应用全局设置而被清空。

如果使用外部参考音频，文件会复制到 `.asmr-dubber/config/references`。GPT-SoVITS、Fish Speech 等需要参考文字的服务必须填写与音频准确对应的原文；MiMo 音色克隆和 IndexTTS2 不需要参考文字。Edge TTS、MiniMax 和 MiMo 的预置/文字设计音色不使用参考音频。英语项目请选择“英语”作为外部参考音频语言，或保持“跟随当前项目源语言”。

## 5. TTS（语音合成）与混音

点击“生成中文配音”只生成缺失或缓存已失效的中文句子，不会开始混音。确认逐句配音后，再点击“混音与输出”，按“音频输出方式”建立中文克隆音轨和/或混音成品。修改时间、音量、声道路由或峰值后，只需再次混音；不必重新等待 TTS。

修改中文、参考音频、合成模型或相关参数后，受影响的 TTS 缓存键会变化；没变化的句子仍会直接复用。

### IndexTTS2 参考方式

IndexTTS2 把音色和情绪分开：

- 音色默认使用项目统一参考句，也可跟随当前句或使用外部音频；
- 情绪默认跟随当前源语言句，也可使用项目参考、音色参考、外部音频或文字描述；
- 同一角色建议保持统一音色参考，多角色项目再考虑逐句参考；
- 参考过短、只有呼吸声或背景音乐太强时，音色更容易漂移。

### Edge TTS

Edge TTS 已包含在基础环境中，不需要 API Key 或本地模型。选择中文音色后可以先试听，再设置语速并生成。它适合没有 NVIDIA GPU、未安装 IndexTTS2，或不需要音色克隆的项目；断网时无法工作。

### MiMo TTS

保存小米 MiMo API Key 后，根据需要选择模型：

- `mimo-v2.5-tts-voiceclone` 使用项目参考句或外部参考音频克隆声音，不需要参考文字；
- `mimo-v2.5-tts` 使用音色 ID；
- `mimo-v2.5-tts-voicedesign` 根据“语气与风格说明”设计声音。

只有音色克隆模型会显示参考音频设置。参考音频会随请求发送到 MiMo。

### MiniMax TTS

保存 MiniMax API Key 后，选择模型和音色 ID，再按需调整语速、音量、音调和情绪。可以填写系统音色，也可以填写账号中已经创建的复刻或设计音色 ID。MiniMax 不直接使用项目参考音频；声音复刻需要先在平台完成。

### 其它 TTS API

程序只调用服务，不会替你启动 GPT-SoVITS、CosyVoice 或 Fish Speech。先确认服务端能独立生成音频，再填写接口地址。GPT-SoVITS 请求会传参考文件路径；Docker 或远程服务必须能通过挂载或路径映射访问该文件。外部并发默认是 2，服务不稳定时先降到 1。

### 中文配音排程

每句中文默认从原字幕开始时间向后偏移 500 ms 进入输出。“中文配音整体偏移”统一移动全部中文，单位为毫秒：负数提前，正数延后。例如 `-200` 表示提前 200 ms，`500` 表示延后 500 ms。负偏移不会让音频越过成品的 0 秒位置。

“尽量放入原时间窗口”使用下一条已启用、已有中文且已经生成 TTS 的句子作为当前句的时间窗口：

```text
当前句可用时长 = 下一句开始时间 - 当前句开始时间
所需加速倍速 = 当前句音频时长 ÷ 当前句可用时长
```

没有冲突时保持原速；发生冲突时只使用刚好能放入窗口的倍速，不会主动把句子加速得更快。如果所需倍速超过“冲突时最大自动加速倍速”，程序保持该上限并允许剩余部分与下一句重叠。默认上限为 1.8×，最大可设为 4×；最后一句没有后续窗口，因此不会自动加速。时间伸缩使用 FFmpeg 保持音调，原始逐句 TTS 文件保持不变；修改这两个参数后只需重新混音。

“上一句结束后再播放下一句”不自动加速。如果上一句在下一句原定开始时间仍未结束，下一句会顺延到上一句播放完毕后再开始。这样可以避免调速和中文互相覆盖，但会逐句累积延迟，最终中文轨及混音成品也可能比原媒体更长。整体偏移在两种方式下都生效；最大自动加速只用于第一种方式。

“音频输出方式”有三种：同时保存混音成品和中文克隆音轨、只保存混音成品、只保存中文克隆音轨。中文克隆音轨保持与原音轨相同的采样率、声道和完整时间轴，适合在外部软件中继续处理；之后把输出方式切回包含混音即可重新加入原音轨，不需要重新生成逐句 TTS。只保存混音成品时不会保留中文轨。

### 响度和峰值

“跟随对应原声”会测量每句对应片段，并让中文按相对值跟随场景强弱；这是默认推荐方式。“所有中文保持统一音量”适合原片段响度变化异常的项目；“保留 TTS 原始音量”不做逐句规范化。一般先调整当前模式下唯一显示的主音量参数，只有遇到噪声放大、削波或切口爆音时才展开高级响度参数。单句、中文中间轨和最终混音各有峰值保护，但不能修复输入或 TTS 本身已经失真的音频。

### 多声道路由

TTS 输出通常是单声道。“自动（优先中置）”决定这条单声道中文该写进原媒体的哪些声道：

- 单声道输入仍输出单声道；
- 立体声输入把中文送到左右两个声道；
- 3.0、5.1、7.1 等多声道输入优先只送到中置声道；
- 无法可靠识别布局时也采用单声道位置的安全回退，避免把人声铺满环绕声道。

“复制到全部声道”会把中文复制到每个声道，通常只用于你明确知道下游需要这种布局的情况。

## 6. 字幕

识别完成后就能生成字幕，不必先做 TTS。可选择：

- 源文 + 中文双语；
- 仅中文；
- 仅源文。

每次会生成 SRT 和 LRC。视频项目还会生成带字幕视频：环境支持时烧录字幕；如果缺少可用的字幕滤镜或编码器，会退回到带可选择字幕轨的封装方式。

字幕时间轴可以使用原源语言边界，也可以跟随中文配音时间。默认可读性限制为每行 22 个字符、最短显示 1 秒、最多 18 字/秒。中文改长后如果字幕闪得太快，应延长边界或降低每秒字符数，而不是只增加单行长度。

## 批量处理作品

顶层“工作台 → 批量处理”页面用于已经解压的 DLsite 作品目录。每次先配置一个作品，再把它加入队列：

1. 输入作品文件夹并扫描；
2. 选择音频版本，决定是否包含特典、样本、Free Talk 和闹钟等附加音轨；
3. 检查“本次将处理的音轨”。卡片可以拖动排序，也可以用上下按钮调整；
4. 检查每条音轨匹配到的字幕和语言。可以换成其它字幕、改为中文/日语/英语，或选择不使用；
5. 选择处理内容、输出类型、成品组织、视频画面和是否内嵌字幕；
6. 加入队列。可以继续扫描其它作品，最后统一开始。

批量扫描只把 SRT、VTT、ASS/SSA 和 LRC 作为字幕候选。语言判断先看明确的文件名或目录标记，再检查字幕内容：出现假名时按日语处理，只有汉字时按中文处理，英文内容按英语处理。判断结果会显示在音轨卡片中，最终以用户在卡片上的选择为准。

带时间轴的中文字幕覆盖当前任务的全部音轨时，会直接成为中文句子表，ASR 和翻译都不会运行，也不会与识别结果叠加。日语或英语字幕直接建立源文时间轴，随后只运行翻译。没有选择字幕的音轨按当前 ASR 设置识别。

“仅生成字幕”适合不需要中文配音的任务。它会完成字幕所需的 ASR 和翻译，跳过参考音频、TTS 与混音，输出双语 SRT/LRC。视频任务勾选“让原声视频带字幕”后，还会生成 `原声字幕版.mp4`；不勾选则保留无字幕原声和外部字幕文件。

输出类型有三种：

- **纯音频**：只生成音频和外部字幕；
- **普通静态视频**：从 0 秒开始使用原声；
- **和谐静态视频**：按自动处理设置降低并延后原声、配音和字幕。

成品组织也有三种：

- **合并成一部**：按音轨顺序生成一个合并成品；
- **每条音轨分别处理并输出**：每条音轨独立处理，不生成合并版；
- **分轨输出 + 合并版**：同时保留两种成品。

扫描后，“视频画面”会显示推荐图片的相对路径和预览。选择其它图片会立即更新预览；选择黑色背景则不使用作品图片。

队列卡片保存加入时的音轨顺序、字幕、输出和标题设置。可以拖动调整执行顺序，也可以编辑、移除或标记重新处理。编辑任务后必须点击“保存队列修改”；取消编辑不会改变原任务。重新处理只清理该任务输出目录中由 AutoFlow 生成的状态和成品，不修改源作品。

固定规则和新作品默认值在“设置 → 自动处理”。其中作品文件夹名称与音轨标题可以分别决定是否翻译。保存默认值不会改写已经加入队列的任务。运行中的任务可以取消，已完成阶段和逐句缓存会保留；输出目录、运行日志和失败原因都能在批量页查看。

## 输出和恢复

最终音频保存在 `output` 下，采用 24-bit WAV。视频项目会尽量保留原画面、原音轨、字幕、附件和 metadata，并附加混音后的音轨。字幕和表格导出分别在 `subtitles` 与 `exports`。

长任务中断后重新打开项目即可继续：

- 已保存的识别、翻译和表格不会因为浏览器关闭而丢失；
- TTS 按句缓存，只重做缺失或输入签名变化的句子；
- 输出先写临时文件，完整完成后才替换正式文件；
- `performance.json` 记录各阶段耗时和缓存命中，不记录 API Key 或 Prompt 正文。

执行 ASR、台本对齐、翻译、TTS、混音或字幕视频时，可以点击“取消当前执行”。程序会停止当前子进程，并在安全检查点退出；已经保存的翻译和逐句 TTS 缓存会保留，ASR 未完成时继续保留取消前的句子表。

“日志与诊断”页显示最近的程序日志，并提供完整日志下载。日志保存在 `.asmr-dubber/logs/asmr-dubber.log`，达到大小限制后自动轮转。API Key 和常见令牌会在写入前隐藏，但日志仍可能包含本机路径、模型名和错误响应，公开提交前应自行检查。

页面底部的“项目诊断”会列出当前阶段、缺少的内容和输出路径。遇到问题先看这里，再查看[排障指南](TROUBLESHOOTING.md)。

## 隐私和密钥

输入媒体和本地模型处理都留在程序目录，但翻译服务和外部 TTS API 会收到完成任务所需的文字或参考音频。是否上传取决于你选择的后端，请阅读相应服务的数据政策。

保存的 API Key 以明文位于 `.asmr-dubber/config/secrets.json`。密码框不回显旧值，只有点击对应的“清除”按钮才会删除。不要分享程序目录、日志中的私人路径、项目媒体或密钥文件。
